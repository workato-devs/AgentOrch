## Task
The requirements below describe the desired behavior. Do not treat their
presentation order as the execution order; determine the workflow from the
requirements, dependencies, and conditions.

Objective
Provide a bounded open-invoice lookup for a supplied churn opportunity and return the appropriate terminal result to the API caller.

Requirements
- A successfully delivered HTTP 200 or HTTP 400 response terminates processing.
- For the supplied request.oppty_id, identify the bounded result of matching open invoices for that churn opportunity. If the result contains exactly 200 invoices, terminate as an error with the message exactly "Amount of invoices found hits table storage limit, please consider increasing search size". If it contains fewer than 200 invoices, return HTTP 200 with the optional invoices array in ascending retrieval order, containing one item per invoice in that bounded result; each item’s id is its invoice ID and number is its invoice number, with blank source values represented as null.
- If invoice retrieval, result-count evaluation, or delivery of the success response raises an error, do not retry; return HTTP 400 with the captured failure message in the required error field.
